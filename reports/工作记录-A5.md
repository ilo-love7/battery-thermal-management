## 2. 环境勘察：五件事决定了后面所有的数字

动笔前跑 `scripts/00_env_check.py` 把模型边界摸清，**五个发现每个都改变了设计**：

| # | 发现 | 本来打算 | 改成 |
|---|---|---|---|
| 1 | Chen2020 熵变系数恒为 0 | 用 Chen2020 做可逆热分解 | 可逆热只能用 Mohtat2020（熵变系数非零） |
| 2 | SPMe 在 3C 电压坍塌（52 s / 0.22 Ah） | SPMe 做快扫、DFN 做精算 | SPMe 退出 3C 以上，全线 DFN |
| 3 | DFN+Chen2020 3C 只交付 38% 容量 | 0.5–5C 全部 Chen2020 直接仿真 | 3C 以上「Mohtat 形状 × 标度律幅度」 |
| 4 | Mohtat2020 DFN 5C 交付 86% | 没打算用 Mohtat | Mohtat 做高倍率形状来源 |
| 5 | x-full 穿厚温差 0.0008 K | "内部梯度"报告穿厚方向 | 梯度改从卷芯径向（两节点）评估 |

**最花时间的是 #3**。一开始看到"3C 温升比 1C 还低"、"可逆热恒为 0"，
第一反应是代码 bug，反复核了产热分解、热容、边界条件，最后发现是
**参数集的物理性质**（熵变系数为 0）和**模型失真**（SPMe 电解液耗尽坍塌）。
教训：PyBaMM 参数集不是"通用电池"，每个都有自己的有效域，**先勘察再建模**。

**#5 是个认知修正**：需求写"观察厚度方向温度梯度"，实测下来叠片方向
根本建立不起温差（~100 μm 叠层 + 箔面内导热极好）。真实的"内部梯度"
在卷芯径向——芯-壳温差 3–35 K，液冷高倍率下表面比芯部低 30 K 以上。
**这不是没做出梯度，是梯度在别的地方**，写进报告 §4。

## 3. 参数层的两个决定

### 3.1 热容不硬编码

一开始抄了个"70 g × 620 J/(kg·K)"的书上值。后来发现 PyBaMM 模型内部
用的是按层加权的体积热容，**书上数和模型数会打架**。改成运行时按层核算
（负极/隔膜/正极/双集流体，ρ·cp·L 求和）并与模型内部值对账（<1%），
写成测试项。Chen2020 几何：42.78 J/K、体积 2.42e-5 m³、面积 0.00531 m²。

### 3.2 两套参数集不混用

Chen2020（21700 圆柱）和 Mohtat2020（5 Ah 软包）几何/热容差异大。
最终分工：**热学量以 Chen2020 几何为准**（两节点、模组、寿命都用它），
**高倍率产热形状借用 Mohtat** 后按标度律 Q=0.782·C^1.79 回缩到 Chen2020 量级。
两套参数在 1–2C 的产热差 1.9–2.9 倍——这是报告里最重要的不确定性声明，
不能藏。

## 4. 标度律外推与交叉验证

0.5–2C（模型域内）拟合 Q=k·C^α：k=0.782、α=1.79、R²=0.99997。
3/4/5C 外推 vs Mohtat 直接仿真：−24.8% / −10.6% / −2.0%。

**3C 偏低 25% 是真的偏差，不是 bug**——原因是熵热项在 3C 反超
（占 70%），构成切换让 C^1.79 外推失效。处理：报告里如实标出偏差，
3C 以上的 Q 用 Mohtat 形状（含熵热）而不是纯标度律。

## 5. 动态工况：US06 从哪来

需求说"US06 等动态工况"。PyBaMM 自带示例工况，但**用实测剖面更有说服力**。
发现 A4 的 CALCE 缓存里有 A123 的 DST/US06/FUDS 实测段，直接复用数据层：
取 600 s 一循环、1 Hz 重采样、按 2.5 Ah 标幺成倍率剖面（均值 0.211C、
峰值 1.46C、回馈 −0.26C），存 `data/us06_crate.csv`。

PyBaMM 的自定义工况接口踩了个坑：一开始用 `pybamm.step.current(函数)`，
发现新版（26.10）**直接支持二维数组驱动**（自动插值+循环），改用数组接口
更稳。另外补了"重复冲击"（3×US06）——单循环温升 <1.4 K，故事立不住；
3 循环累积温升（自然 1.9 K / 液冷 0.2 K）才把 PCM 削峰和液冷优势区分开。

## 6. 流水线里修掉的三个实打实的问题

1. **图缺中文字形**：matplotlib 默认字体无 CJK，第一轮图全是豆腐块。
   加了 SimHei/Microsoft YaHei 回退链后重出全部 16 张图。
2. **变量名在新版 PyBaMM 改了**：`Surface temperature [C]` 只剩
   `[K]` 版本，03 脚本 KeyError。改成从 `variable_names()` 里筛
   温度类变量再按名字取，避免再被 API 改动打到。
3. **寿命偏差符号定义反了**：`mean_temperature_bias` 一开始算的
   "寿命偏差"方向与 Jensen 不等式方向相反（平均温度低估损伤 ⇒
   寿命高估，符号写反）。测试 `test_mean_temperature_bias_direction`
   抓出来后修正，并把定义写死在 docstring 里。

x-full 热模型还有个坑：Chen2020 缺极耳/表面换热键，逐个补参太慢，
写了自动补参重试循环（按错误信息解析缺失键 → 猜合理值 → 重试），
30 次内收敛。**这个循环本身就是个可复用的小工具**。

## 7. 测试设计：15 项都测"物理"不测"跑通"

测试不是"import 不报错"，每项都有一条物理防线：

| 测试 | 防的事故 |
|---|---|
| 热容按层核算 = PyBaMM 内部值（<1%） | 书上抄的数和模型用的数打架 |
| 两节点稳态温差 = 解析解（逐位一致） | 网络方程写错符号 |
| 辨识闭环恢复真参数（含噪声） | 最小二乘过拟合/欠参数化 |
| Arrhenius 损伤方向与寿命比一致 | 符号定义反了（§6.3，已中过一次） |
| 标度律外推偏差在声明范围内 | 外推悄悄跑出可信域 |
| US06 剖面能量/峰值守恒 | 数据重采样把峰值抹平 |
| 5 种方案 h 区间单调、PCM 热容非负 | 参数表录入错误 |
